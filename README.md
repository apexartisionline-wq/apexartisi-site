# Apex

Η εφαρμογή της **apex/rtisi online**: μέλη, ομάδες, ατομικές, ημερολόγιο και κόκκινο κουμπί σε ένα μέρος.
Χτίζεται με βάση το έγγραφο «Apex — Σχέδιο εφαρμογής» (26/9/2026). Αυτό το repo περιέχει την **πρώτη φάση**.

Τεχνολογία: Next.js 15 (web app που «εγκαθίσταται» στο κινητό ως «Apex»), PostgreSQL μέσω Prisma.
Χωρίς κώδικα παρακολούθησης τρίτων· αυστηρό Content-Security-Policy.

## Τι κάνει ο καθένας

| Ρόλος | Διαδρομή | Τι κάνει |
| --- | --- | --- |
| Μέλος | `/m` | «Πού βρίσκομαι» (μέρα προγράμματος, συνεδρία Χ από Ν), κείμενο της ημέρας (09:00), φόρμες θεματικής (Δ/Τ/Π 09:30), «Μπες στην ομάδα» (Δ/Τ/Π 18:00, καταγράφει παρουσία), ημερολόγιο ανάκαμψης (20:00), κράτηση ατομικών (Δευτέρα έως 21:00, μόνο ώρες με ελεύθερη θέση), «Μπες στη συνεδρία σου», κόκκινο κουμπί |
| Θεραπευτής | `/t` | Πρόγραμμα ημέρας, προηγούμενα σημειώματα του μέλους (και άλλων θεραπευτών), σημείωμα μετά τη συνεδρία |
| Εύα | `/admin` | Θέσεις ανά ώρα/μέρα (έως 4) με θεραπευτή, ραντεβού εβδομάδας, ποιος δεν μπήκε, κύκλοι που λήγουν, διάρκεια συνεδρίας, άνθρωποι και κωδικοί, κείμενα/φόρμες, αρχείο κόκκινου κουμπιού, ρυθμίσεις |

Όλες οι ώρες, οι μέρες, τα δωμάτια Zoom, το όνομα και το λογότυπο είναι **ρυθμίσεις** (`/admin/settings`), όχι «καρφωμένα».
Όλες οι ώρες είναι ώρα Ελλάδας, ανεξάρτητα από τον server.

### Κόκκινο κουμπί
1. Το μέλος ακούει το «μήνυμα από τον εαυτό του» (το ηχογραφεί στο `/m/self-message`).
2. Άσκηση αναπνοής.
3. «Θέλω να μιλήσω με άνθρωπο» (διαθέσιμο σε κάθε βήμα) → μήνυμα στην ομάδα Telegram με κουμπί «Το αναλαμβάνω».
   Στο Telegram πηγαίνει **μόνο το όνομα**. Ο πρώτος που πατά το παίρνει, οι άλλοι το βλέπουν, το μέλος βλέπει «ο/η … σε παίρνει τώρα».
   Αν δεν το αναλάβει κανείς σε 10 λεπτά, ξαναστέλνεται και το μέλος βλέπει γραμμή βοήθειας και 112.
   Αν το Telegram δεν απαντά ή δεν έχει ρυθμιστεί, το μέλος βλέπει **αμέσως** γραμμή βοήθειας και 112.

## Εγκατάσταση

```bash
cp .env.example .env        # συμπλήρωσε DATABASE_URL κ.λπ.
npm install
npm run db:deploy           # δημιουργεί τους πίνακες
ADMIN_USERNAME=eva ADMIN_NAME="Εύα" npm run db:seed   # τυπώνει τον πρώτο κωδικό
npm run build && npm start
```

Τοπικά: `npm run dev`, tests: `npm test`, έλεγχος τύπων: `npm run lint`.

### Φιλοξενία (δεδομένα στην Ευρώπη)
Χρειάζεται μια βάση PostgreSQL και ένας Node.js server, και τα δύο σε περιοχή της ΕΕ
(π.χ. Frankfurt). Οποιοσδήποτε πάροχος κάνει· σημασία έχει η περιοχή και η σύμβαση επεξεργασίας (DPA).

### Telegram
1. Δημιουργία bot με τον @BotFather → `TELEGRAM_BOT_TOKEN`.
2. Προσθήκη του bot στην ομάδα των τριών θεραπευτών → `TELEGRAM_CHAT_ID` (αρνητικός αριθμός).
3. Webhook:
   ```bash
   curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
     -d url="$APP_URL/api/telegram" -d secret_token="$TELEGRAM_WEBHOOK_SECRET" \
     -d allowed_updates='["callback_query"]'
   ```
4. Σε κάθε θεραπευτή, στο `/admin/people`, το Telegram user ID του (για να φαίνεται το σωστό όνομα).

### Έλεγχος 10 λεπτών
Κάθε λεπτό: `curl -X POST -H "Authorization: Bearer $CRON_SECRET" $APP_URL/api/cron/help`.
(Όσο η σελίδα του μέλους είναι ανοιχτή, κάνει τον ίδιο έλεγχο και μόνη της.)

## Τι δεν έχει γίνει ακόμα

Από την πρώτη φάση:
- **Google ημερολόγια**: τα ραντεβού δεν περνάνε ακόμα αυτόματα.
- **Διάρκεια από το Zoom**: η Εύα τη γράφει με το χέρι στα Ραντεβού· η αυτόματη ανάγνωση από τις αναφορές του Zoom θέλει λογαριασμό API.
- **Ειδοποιήσεις στο κινητό** (με ουδέτερα κείμενα, π.χ. «Το κείμενό σου είναι έτοιμο»): δεν έχουν μπει· το μέλος βλέπει τα πάντα όταν ανοίγει το app.

Εκτός πρώτης φάσης (σύμφωνα με το σχέδιο): δείκτης πορείας (όταν σταθεροποιηθεί), οικονομικά, κόκκινο κουμπί μέσα στο app, βίντεο μέσα στο app.

Πριν μπουν τα πρώτα μέλη: ευρήματα GDPR (συγκατάθεση για δεδομένα υγείας, πολιτική απορρήτου, ΕΑΠΔ)
και η γραμμή βοήθειας στις ρυθμίσεις.
